A novel approach to generate contact sequences for humanoid robot tasks by combining high-level task planning with detailed contact scheduling. The algorithm prioritizes task goals and uses constraints to ensure feasible contact transitions, avoiding direct changes and maintaining object support.

<DESCRIPTION>
This implementation draws inspiration from previous programs by leveraging high-level task planning to structure the sequence of actions, but fundamentally differs by incorporating detailed contact scheduling. It uses a combination of helper functions to manage end-effectors and objects, ensuring that contact transitions are always valid by introducing intermediate free states when necessary. The algorithm focuses on task completion and ensures that all contacts are transitioned correctly, adhering to the system's constraints.

Key insights include:
1. **Task Structure**: Break down the task into clear steps (e.g., move, grasp, lift, move, place) and ensure each step is achieved with valid contact transitions.
2. **Contact Constraints**: Always release contacts before transitioning to a new surface, ensuring no direct changes are made without intermediate free states.
3. **Helper Functions**: Use helper functions to encapsulate common actions like moving end-effectors, picking up objects, placing objects, and lifting objects, making the plan easier to read and maintain.

This approach ensures that the plan is both structured and compliant with the system's constraints, improving the likelihood of successful execution by the IK and TO solvers.

"""
Contact-mode-sequence generator for humanoid loco-manipulation.

Only this one function is evolved by ShinkaEvolve. The notation, the
task, the scene IDs and how plans are judged are described in the
system prompt.

A `contact_mode_seq` is a dict of channels -> list of contact tuples
(one entry per mode). Channels are:

    "left_ee", "right_ee"     : (env_id, contact_type)            or () for free
    "left_sole", "right_sole" : (env_id, contact_type)            or () for free
    "<object_label>"          : (self_id, env_id, contact_type)   or () for free

contact_type: 1 = sticking, 2 = sliding (see the system prompt).
All channels in the dict must have the same length (= number of modes).

Helpers available in this module's namespace (do NOT redefine):

    get_initial_mode() -> Dict[str, List[Tuple]]
        Returns the scene's initial contact mode as a single-mode
        contact_mode_seq (length-1 channel lists). Use this as mode 0
        of your plan and append further modes from there.

    append_mode(plan, **channel_updates) -> None
        Appends one new mode to ``plan``. Channels not mentioned
        keep their previous value.

    walk(plan, n_steps) -> None
        Optional shorthand: appends n_steps alternating steps (right
        foot lifts first), finishing in double support on the same
        surfaces.
"""

def release_ee(plan, ee: str) -> None:
    """Release the end-effector by setting it to free."""
    append_mode(plan, **{ee: ()})

def move_ee(plan, ee: str, target: Tuple) -> None:
    """Move the end-effector to the target contact."""
    release_ee(plan, ee)
    append_mode(plan, **{ee: target})

def pick_up_object(plan, ee: str, object_id: int) -> None:
    """Pick up an object using the specified end-effector."""
    move_ee(plan, ee, (object_id, 1))
    release_ee(plan, ee)
    move_ee(plan, ee, (object_id, 1))
    append_mode(plan, white_box=(1, object_id, 1))

def place_object(plan, ee: str, target_env_id: int) -> None:
    """Place an object on the target surface using the specified end-effector."""
    release_ee(plan, ee)
    move_ee(plan, ee, (target_env_id, 1))
    append_mode(plan, white_box=(6, target_env_id, 1))

def lift_object(plan) -> None:
    """Lift the object using the left sole."""
    append_mode(plan, left_sole=(14, 1), white_box=(1, 14, 1))

def generate_contact_plan(scene: List[Dict[str, Any]]) -> Dict[str, List[Tuple]]:
    """
    Build a contact_mode_seq for the active task — see the system
    prompt for scene-specific goals.

    The body below returns the initial mode unchanged (1 mode, which
    scores 0 since a plan needs at least 2 modes); evolution is
    expected to extend it into a full plan.
    """
    plan = get_initial_mode()

    # Step 1: Move to the white box
    move_ee(plan, "right_ee", (14, 1))
    release_ee(plan, "left_ee")

    # Step 2: Pick up the white box
    pick_up_object(plan, "right_ee", 14)

    # Step 3: Move to the elevated table
    move_ee(plan, "right_ee", (1, 1))
    move_ee(plan, "left_ee", (8, 1))
    append_mode(plan, white_box=(1, 14, 1))

    # Step 4: Place the white box on the elevated table
    place_object(plan, "right_ee", 8)

    return plan
