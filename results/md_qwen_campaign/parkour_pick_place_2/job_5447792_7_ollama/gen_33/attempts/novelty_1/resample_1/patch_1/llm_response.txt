A novel approach that optimizes the contact sequence by breaking down the task into smaller, more manageable steps. It ensures that each transition between surfaces is smooth and follows the solver's rules, avoiding abrupt changes that lead to infeasibility.

<DESCRIPTION>
The current approach to generating the contact plan involves lifting the box, moving it towards the table, and then placing it. However, the plan often fails due to abrupt transitions and missing intermediate steps. This new approach addresses these issues by:

1. **Breaking Down the Task**: The task is divided into smaller steps, ensuring that each transition is smooth and follows the solver's rules.
2. **Ensuring Smooth Transitions**: Each contact change is handled with intermediate free modes to ensure that the solver can manage the transitions.
3. **Using Helper Functions**: Functions are used to encapsulate specific actions, making the code more modular and easier to maintain.
4. **Optimizing Steps**: The number of walking steps is optimized to ensure that the robot can reach the desired position without exceeding the solver's limits.

These changes aim to improve the feasibility of the plan and reduce the number of solver violations.

"""
Contact-mode-sequence generator for humanoid loco-manipulation.

Only this one function is evolved by ShinkaEvolve. The notation, the
task, the scene IDs and how plans are judged are described in the
system prompt.

A `contact_mode_seq` is a dict of channels -> list of contact tuples
(one entry per mode). Channels are:

    "left_ee", "right_ee"     : (env_id, contact_type)            or () for free
    "left_sole", "right_sole" : (env_id, contact_type)            or () for free
    "<object_label>"          : (self_id, env_id, contact_type)   or () for free

contact_type: 1 = sticking, 2 = sliding (see the system prompt).
All channels in the dict must have the same length (= number of modes).

Helpers available in this module's namespace (do NOT redefine):

    get_initial_mode() -> Dict[str, List[Tuple]]
        Returns the scene's initial contact mode as a single-mode
        contact_mode_seq (length-1 channel lists). Use this as mode 0
        of your plan and append further modes from there.

    append_mode(plan, **channel_updates) -> None
        Appends one new mode to ``plan``. Channels not mentioned
        keep their previous value.

    walk(plan, n_steps) -> None
        Optional shorthand: appends n_steps alternating steps (right
        foot lifts first), finishing in double support on the same
        surfaces.
"""

def lift_box(plan: Dict[str, List[Tuple]]) -> None:
    # Step 1: Lift the white box off the floor
    append_mode(plan, white_box=())
    append_mode(plan, white_box=(6, 1, 2))  # Sliding contact to lift the box slowly
    append_mode(plan, white_box=(6, 1, 1))  # Sticking contact to ensure stability

def move_to_table(plan: Dict[str, List[Tuple]]) -> None:
    # Step 2: Move the white box to the table
    append_mode(plan, white_box=(6, 1, 2))  # Sliding contact to move the box closer to the table
    walk(plan, 5)  # Walk to the table
    append_mode(plan, white_box=(6, 8, 2))  # Sliding contact to align with the table
    append_mode(plan, white_box=(6, 8, 1))  # Sticking contact to place the box on the table

def generate_contact_plan(scene: List[Dict[str, Any]]) -> Dict[str, List[Tuple]]:
    """
    Build a contact_mode_seq for the active task — see the system
    prompt for scene-specific goals.

    The body below returns the initial mode unchanged (1 mode, which
    scores 0 since a plan needs at least 2 modes); evolution is
    expected to extend it into a full plan.
    """
    plan = get_initial_mode()

    lift_box(plan)
    move_to_table(plan)

    return plan
