Improved Contact Plan Generator
</NAME>

<DESCRIPTION>
The prior programs attempted to generate a contact plan for a humanoid robot to pick up a yellow box and place it on a distant table. However, they faced issues with contact transitions, where the object transitioned directly from one contact to another without a free state in between. This violates the solver's rule that each contact must be released before touching a different surface.

To address this, the new approach involves carefully managing the contact transitions for both the robot's limbs and the object. The plan will be structured to ensure that each contact change adheres to the solver's rules. Specifically, the plan will:

1. Walk to the yellow box.
2. Release the yellow box contact and then pick it up with the right hand.
3. Walk to the distant table.
4. Release the yellow box contact and then place it on the table with the right hand.

The key insight is to ensure that any change in contact (either for the robot's limbs or the object) is preceded by a free state, adhering strictly to the solver's rules.

"""
Contact-mode-sequence generator for humanoid loco-manipulation.

Only this one function is evolved by ShinkaEvolve. The notation, the
task, the scene IDs and how plans are judged are described in the
system prompt.

A `contact_mode_seq` is a dict of channels -> list of contact tuples
(one entry per mode). Channels are:

    "left_ee", "right_ee"     : (env_id, contact_type)            or () for free
    "left_sole", "right_sole" : (env_id, contact_type)            or () for free
    "<object_label>"          : (self_id, env_id, contact_type)   or () for free

contact_type: 1 = sticking, 2 = sliding (see the system prompt).
All channels in the dict must have the same length (= number of modes).

Helpers available in this module's namespace (do NOT redefine):

    get_initial_mode() -> Dict[str, List[Tuple]]
        Returns the scene's initial contact mode as a single-mode
        contact_mode_seq (length-1 channel lists). Use this as mode 0
        of your plan and append further modes from there.

    append_mode(plan, **channel_updates) -> None
        Appends one new mode to ``plan``. Channels not mentioned
        keep their previous value.

    walk(plan, n_steps) -> None
        Optional shorthand: appends n_steps alternating steps (right
        foot lifts first), finishing in double support on the same
        surfaces.
"""

def generate_contact_plan(scene: List[Dict[str, Any]]) -> Dict[str, List[Tuple]]:
    """
    Build a contact_mode_seq for the active task — see the system
    prompt for scene-specific goals.

    The body below returns the initial mode unchanged (1 mode, which
    scores 0 since a plan needs at least 2 modes); evolution is
    expected to extend it into a full plan.
    """
    plan = get_initial_mode()

    # Walk to the yellow box
    walk(plan, 10)

    # Release yellow_box contact
    append_mode(plan, yellow_box=())

    # Pick up the yellow box with the right hand
    append_mode(plan, right_ee=(8, 1))
    append_mode(plan, yellow_box=(1, 8, 1))

    # Walk to the distant table
    walk(plan, 10)

    # Release yellow_box contact
    append_mode(plan, yellow_box=())

    # Place the yellow box on the table with the right hand
    append_mode(plan, right_ee=())
    append_mode(plan, yellow_box=(6, 2, 1))

    return plan
